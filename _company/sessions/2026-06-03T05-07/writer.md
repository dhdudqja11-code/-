# 🛡️ [개발자용] 리스크 데이터 입력 및 시스템 시각화 가이드 v1.0
*(The Core Data Schema for Authority Proof)*

## I. 핵심 구조 정의: JSON 스키마 (Data Input Script)

모든 법적 위험 데이터를 다음의 표준화된 JSON 포맷에 따라 구축해야 합니다. 이 필드들은 시스템이 정보를 파싱하고 분석할 때 필수적인 '메타데이터' 역할을 수행합니다.

```json
{
  "Record_ID": "unique-identifier-YYYYMMDD", 
  "Scenario_Category": "[GDPR/AI Bias/Data Sovereignty]", // 핵심 리스크 영역 분류 (필수)
  "Regulation_Source": { // 법적 근거의 권위 부여
    "Regulation_Name": "글로벌 규제 명칭 (예: GDPR, CCPA)", 
    "Article_ID": "특정 조항 ID (예: Article 5.1)", 
    "Jurisdiction": "규제를 적용하는 지역/국가 (예: EU, USA)"
  },
  "Pain_Point_Schema": { // 위반 메커니즘과 고통점의 정량화
    "Violation_Mechanism": "[구체적인 기술적/행동적 위반 방식]", 
    "Observed_Vulnerability": "현재 시스템에서 감지 가능한 취약점 (예: Non-encrypted API endpoint)",
    "Financial_Impact_Estimate": { // 가장 중요한 정량화된 확신 근거
      "Min_Loss_USD": "최소 예상 손실액 ($X,XXX,XXX)", 
      "Max_Loss_USD": "최대 예상 책임액 ($Y,YYY,YYY)", 
      "Basis_Explanation": "[손실 산정의 법률적/재무적 근거 간략 설명]"
    }
  },
  "Authority_Solution_Schema": { // 시스템이 제공하는 '방어권' 정의
    "Required_Functionality": "해결을 위해 필수적인 기능 명칭 (예: Zero-Trust Auth)", 
    "Defense_Proof_Level": "확보되는 권위 수준 (예: Class A - 법적 분쟁 대응 가능)",
    "Mitigation_Description": "우리가 제공하는 시스템적 증명 과정 설명 (기술 용어 최소화)"
  }
}
```

## II. UX 스토리보드 및 카피라이팅 가이드라인

각 JSON 필드가 시스템 내부에서 어떤 애니메이션과 톤으로 사용자에게 전달되어야 하는지 정의합니다. 이는 '정보 나열'이 아닌, **'위험 인식의 감정적 여정'**을 설계하는 것이 핵심입니다.

| 데이터 항목 (JSON Field) | 시각화 방식 및 스토리보드 가이드 | Writer/UX 카피라이팅 (사용자에게 보여줄 문구 톤앤매너) |
| :--- | :--- | :--- |
| **`Scenario_Category`** | 화면 상단에 경고 패널 형태로 배치. 배경은 어둡고, 위험도가 높은 항목일수록 깜빡이는 효과(Blinking Effect) 적용. | "현재 귀하의 비즈니스는 [데이터 프라이버시] 영역에서 미해결된 리스크를 안고 있습니다." (긴장감 조성) |
| **`Regulation_Source`** | 데이터 구조가 '규정'이라는 권위 있는 틀에 담겨 있음을 시각화. 규제 명칭이 고전적인 서체와 함께 팝업되며 신뢰성을 부여. | "이는 단순한 산업 관행이 아닙니다. [EU GDPR]의 **명확한 법적 조항**을 근거로 합니다." (전문성 강조) |
| **`Violation_Mechanism`** | 핵심 동작 애니메이션. JSON 값이 입력되는 순간, 관련 시스템 구조(데이터 플로우 다이어그램 등)에 빨간색으로 '균열' 또는 '누락된 연결 고리'가 표시되어야 함. | "시스템이 감지한 위반 메커니즘: **[암호화되지 않은 API 통신]**입니다. 이는 데이터 흐름의 핵심적인 취약점입니다." (문제 지적) |
| **`Financial_Impact_Estimate`** | 화면 중앙에 가장 크고, 굵게, 그리고 **숫자만으로** 제시되어야 함. 애니메이션은 숫자가 '계산'되거나 '증폭'되는 과정을 거쳐 공포감을 극대화해야 함. | "**[최소 $X$원]부터 [최대 $Y$원] 규모의 법적 책임이 예상됩니다.** 이 수치는 추측이 아닌, 규정 기반의 냉정한 예측치입니다." (권위적 확신 제공) |
| **`Mitigation_Authority_Level`** | 위험 경고(빨간색/불안) $\rightarrow$ 시스템 개입(파란색/통제)으로 색상 전환. 마치 방패나 보호막이 전경에 펼쳐지는 듯한 애니메이션. | "당신에게 필요한 것은 '임시방편'이 아닙니다. 이는 법적 논쟁에서 당신의 입장을 무조건적으로 지켜줄 **시스템적인 '증명권(Authority)'**입니다." (해결책 제시) |
