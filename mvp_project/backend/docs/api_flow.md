# ⚙️ MVP 핵심 API 로직 흐름도 (The Content Architect Engine)\n\n## 1. 목표: 구조화된 결과물 생성 및 검증\n*   **핵심 원칙:** LLM에게 '글쓰기'를 맡기는 것이 아니라, '최적의 청사진(Blueprint)을 짜도록' 지시해야 합니다.\n*   **출력 포맷 강제:** 모든 중간 단계와 최종 출력은 반드시 JSON Schema를 통해 구조화되어야 합니다.\n\n## 2. 엔드포인트 정의 (FastAPI)\n**POST /api/v1/generate_content**\n\n### ✅ 요청 바디 (Request Body - Pydantic Model)\n| Field | Type | Description | 예시 값 |\n| :--- | :--- | :--- | :--- |\n| `target_keyword` | String | 핵심 검색 키워드. 필수로 검증되어야 함. | `AI 프롬프트 엔지니어링` |\n| `content_type` | Enum | 콘텐츠 유형 (blog, sns, report 등). | `blog` |\n| `persona` | Object | 타겟 페르소나 정보. (age, job, pain_point).\n| `tone_of_voice` | Enum | 글의 톤앤매너 (professional, friendly, urgent).\n\n### ✨ 로직 처리 단계 (Backend Logic Flow)\n\n**Step 1: 입력 검증 및 전처리 (Validation & Pre-processing)**\n*   요청 파라미터가 모두 존재하고 유효한지 확인. (예: `target_keyword`에 특수문자만 있는지 등).\n*   사용자 인증/토큰 검증을 통해 `user_id` 확보.\n\n**Step 2: 1차 LLM 호출 - 구조 설계 (Blueprint Generation)**\n*   **프롬프트 목표:** 주어진 키워드와 페르소나에 최적화된 '논리적인 목차(Structure)'를 JSON 형식으로 요청합니다. (예: H1, H2, H3 태그의 계층구조 정의).\n*   **출력 포맷:** `{"sections": [{ "level": 2, "heading": "...", "expected_keywords": ["..."] }, ... ]}`\n*   **검증 루프 (Self-Correction):** 구조가 논리적으로 비약되는 부분이 있는지 내부 로직으로 검토하고, LLM에게 '이 부분을 보강하라'고 재요청할 수 있습니다. (최대 1회)\n\n**Step 3: 2차 LLM 호출 - 콘텐츠 작성 (Content Filling)**\n*   **프롬프트 목표:** Step 2에서 받은 **구조(Structure)**를 기반으로, 각 섹션별로 구체적인 내용을 채워 넣도록 요청합니다. 단순히 글을 쓰는 것이 아니라, *각 구조에 맞는 분량과 깊이*를 요구해야 합니다.\n*   **출력 포맷:** 최종 마크다운 또는 HTML 형태의 텍스트.\n\n**Step 4: 데이터 저장 및 응답 (Persistence & Response)**\n*   최종적으로 완성된 구조(JSON)와 콘텐츠(TEXT)를 `generated_content` 테이블에 트랜잭션으로 저장합니다. (사용자 ID 바인딩 필수).\n*   클라이언트에게 성공 메시지와 함께, **저장된 콘텐츠의 미리 보기 데이터**를 반환합니다.\n\n## 3. 오류 처리 및 예외 상황\n*   LLM API 호출 실패: 재시도 로직(Retry Mechanism) 구현 (Exponential Backoff 추천).\n*   데이터 유효성 검사 실패: 사용자에게 명확한 에러 메시지 제공 (예: "키워드가 너무 일반적입니다. 구체적인 상품명을 넣어주세요.").\n
